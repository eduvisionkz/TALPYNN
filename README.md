# Talpyn — бастауыш сынып математикасына арналған білім беру платформасы

Talpyn — 1–4 сынып оқушыларына арналған интерактивті математика платформасы: React +
TypeScript + Vite фронтенді, Supabase (аутентификация, PostgreSQL, файл қоймасы) бэкенді.

Бұл нұсқаулық терең бағдарламалау білімі жоқ адамға арналған — әр қадам ретімен жазылған.

## 1. Компьютерде іске қосу

1. [nodejs.org](https://nodejs.org) сайтынан Node.js 20 нұсқасын (немесе жаңасын) жүктеп орнатыңыз.
2. Осы жоба қалтасында терминал ашыңыз.
3. Тәуелділіктерді орнатыңыз:
   ```bash
   npm install
   ```
4. `.env.example` файлын көшіріп, `.env.local` деп атаңыз:
   ```bash
   cp .env.example .env.local
   ```
5. Жобаны іске қосыңыз:
   ```bash
   npm run dev
   ```
   Терминалда шыққан сілтемені (әдетте `http://localhost:5173`) браузерде ашыңыз.

`.env.local` файлы толтырылмаса, платформа **бос/ақ экран көрсетпейді** — бас бет пен
тақырыптар каталогы жергілікті `src/data/topics.ts` тізімінен демо режимде ашылады (бетте
сары ескерту жолағы шығады), тек сабақ мазмұны, кіру, тіркелу және деректерді сақтау
қолжетімсіз болады (себебі бұлар тек Supabase-те сақталады). Толық жұмыс үшін 2-бөлімді
орындаңыз.

**Ескерту**: бұл жобаны `index.html` файлын тікелей екі рет басып ашуға болмайды (`file://`
хаттамасы) — Vite жобалары модульдер мен маршрутизацияны нақты dev/build серверінен талап
етеді. Осылай ашсаңыз, платформа мұны танып, бос экранның орнына түсінікті хабарлама
көрсетеді: «Бұл жобаны тікелей index.html файлы арқылы ашуға болмайды. `npm run dev`
командасын пайдаланыңыз немесе сайтты Vercel арқылы жариялаңыз.» Дұрыс жолы — жоғарыдағы
`npm run dev` (жергілікті) немесе 6-бөлімдегі Vercel жариялау қадамдары.

## 2. Supabase жобасын құру

1. [supabase.com](https://supabase.com) сайтында тіркеліп, жаңа жоба (`New project`) құрыңыз.
2. Сол жақ мәзірден **SQL Editor** бөліміне өтіңіз.
3. `supabase/migrations/` қалтасындағы файлдарды **дәл осы ретпен** (нөмірі бойынша)
   ашып, әрқайсысының мазмұнын SQL Editor-ге көшіріп, `Run` батырмасын басыңыз:
   - `0001_schema.sql` — кестелер;
   - `0002_role_functions.sql` — рөлдерді тексеру функциялары;
   - `0003_rls.sql` — Row Level Security ережелері;
   - `0004_storage.sql` — файл қоймасы (`materials` bucket);
   - `0005_seed_achievements.sql` — жетістіктердің бастапқы тізімі;
   - `0006_seed_topics.sql` — барлық 113 тақырып (жоба ретінде);
   - `0007_first_lesson.sql` — «10 көлеміндегі сандардың құрамы» тақырыбын толық
     интерактивті мазмұнмен жариялайды;
   - `0008_grade1_logic_lessons.sql` — 1-сынып «Логика және функционалдық
     сауаттылық» бағытының барлық 15 тақырыбын толық интерактивті мазмұнмен
     жариялайды;
   - `0009_grade2_logic_lessons.sql` — 2-сынып «Логика және функционалдық
     сауаттылық» бағытының барлық 12 тақырыбын жариялайды;
   - `0010_grade3_logic_lessons.sql` — 3-сынып «Логика және функционалдық
     сауаттылық» бағытының барлық 15 тақырыбын жариялайды;
   - `0011_grade4_logic_lessons.sql` — 4-сынып «Логика және функционалдық
     сауаттылық» бағытының барлық 11 тақырыбын жариялайды — осымен «Логика»
     бағытының барлық 53 тақырыбы толық аяқталды;
   - `0012_grade1_base_lessons.sql` — 1-сынып «Негізгі математика» бағытының
     қалған 14 тақырыбын (флагман сабақтан басқасы) толық интерактивті
     мазмұнмен жариялайды;
   - `0013_grade2_base_lessons.sql` — 2-сынып «Негізгі математика» бағытының
     барлық 15 тақырыбын толық интерактивті мазмұнмен жариялайды;
   - `0014_grade3_base_lessons.sql` — 3-сынып «Негізгі математика» бағытының
     барлық 15 тақырыбын толық интерактивті мазмұнмен жариялайды;
   - `0015_grade4_base_lessons.sql` — 4-сынып «Негізгі математика» бағытының
     барлық 15 тақырыбын толық интерактивті мазмұнмен жариялайды — осымен
     **барлық 113 тақырық толық аяқталды**.

   0008–0015 `scripts/generateLessonSeed.ts` арқылы
   `src/data/lessonContent/grade1Logic.ts` / `grade2Logic.ts` / `grade3Logic.ts` /
   `grade4Logic.ts` / `grade1Base.ts` / `grade2Base.ts` / `grade3Base.ts` /
   `grade4Base.ts` файлдарынан автоматты түрде жасалған.
4. **Project Settings → API** бөліміне өтіп, `Project URL` және `anon public` (немесе
   `publishable`) кілтін көшіріп алыңыз. **`service_role` кілтін ешқашан көшірмеңіз** —
   ол бразуерге немесе GitHub-қа түспеуі керек.

## 3. Алғашқы пайдаланушыны әкімші ету

1. Сайт арқылы (немесе `npm run dev` кезінде) әдеттегідей тіркеліңіз — жүйе сізді
   автоматты түрде «оқушы» ретінде жазады.
2. Supabase консолінде **Table Editor → profiles** кестесін ашыңыз.
3. Өз жазбаңызды тауып, `role` бағанын `student`-тен `admin`-ге ауыстырыңыз.
4. Сайтта қайта кіріңіз (шығып, қайта кіру) — енді «Басқару» бөлімі көрінеді.

Мұғалім тағайындау үшін де дәл осылай, бірақ `role` мәнін `teacher` етіп қойыңыз.
Әдепкі бойынша ешкім өзіне-өзі мұғалім немесе әкімші рөлін бере алмайды — мұны тек
қолданыстағы әкімші ғана `profiles` кестесі арқылы жасай алады.

## 4. Айнымалы орталарды қосу

`.env.local` файлын ашып, 2-бөлімде көшірген мәндерді енгізіңіз:

```env
VITE_SUPABASE_URL=https://ВАШ_ПРОЕКТ.supabase.co
VITE_SUPABASE_ANON_KEY=ВАШ_КІЛТ
```

Файлды сақтап, `npm run dev` командасын қайта іске қосыңыз.

## 5. GitHub-қа жүктеу

1. [github.com](https://github.com) сайтында жаңа бос репозиторий құрыңыз.
2. Осы жоба қалтасында терминалда:
   ```bash
   git init
   git add .
   git commit -m "Talpyn platform"
   git branch -M main
   git remote add origin https://github.com/СІЗДІҢ_АККАУНТ/РЕПОЗИТОРИЙ.git
   git push -u origin main
   ```

`.env.local` файлы `.gitignore` тізімінде тұр, сондықтан ол GitHub-қа жүктелмейді —
бұл дұрыс, өйткені онда жеке кілт бар.

## 6. Vercel-ге жариялау

1. [vercel.com](https://vercel.com) сайтына GitHub аккаунтыңызбен кіріңіз.
2. **Add New → Project** батырмасын басып, 5-бөлімде жүктеген репозиторийді таңдаңыз.
3. **Framework Preset** мәнін `Vite` етіп қалдырыңыз (Vercel оны автоматты анықтауы тиіс).
4. **Environment Variables** бөлімінде екі айнымалыны қосыңыз:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
5. **Deploy** батырмасын басыңыз. Бірнеше минуттан кейін сайтыңыздың сілтемесі шығады.

`vercel.json` файлы React Router маршруттарын дұрыс өңдейді — беттерді жаңартқанда
(мысалы, `/topics` бетінде F5 басқанда) 404 қатесі шықпайды.

## 7. Сайтты жаңарту

Кодқа өзгеріс енгізген сайын:

```bash
git add .
git commit -m "Өзгеріс сипаттамасы"
git push
```

Vercel GitHub-тағы `main` тармағын бақылап тұрады және әр push сайын сайтты автоматты
түрде қайта жариялайды.

## 8. Дерекқордың сақтық көшірмесі

1. Supabase консолінде **Database → Backups** бөліміне өтіңіз (тарифке байланысты
   автоматты күнделікті көшірмелер қолжетімді болуы мүмкін).
2. Қолмен көшірме алу үшін **SQL Editor**-де немесе `pg_dump` арқылы (Supabase
   құжаттамасындағы қосылу мәліметтерін пайдаланып) толық дамп жасауға болады:
   ```bash
   pg_dump "postgresql://postgres:[ПАРОЛЬ]@[HOST]:5432/postgres" > talpyn-backup.sql
   ```
3. Файлдарды (суреттер, PDF, видео) сақтық көшірмелеу үшін **Storage** бөлімінен
   `materials` bucket-ін жүктеп алуға болады.

## 8.1. Ақаулықтарды жою

| Белгі | Ықтимал себеп және шешім |
| --- | --- |
| Ақ/бос экран | Браузер консолін (F12 → Console) ашыңыз — `ErrorBoundary` компоненті кез келген рендер қатесін ұстап, түсінікті хабарлама көрсетуі тиіс. Егер шынымен бос экран болса, бұл жобаны `file://` арқылы тікелей ашқаныңызды білдіруі мүмкін (жоғарыдағы ескертуді қараңыз) — `npm run dev` немесе Vercel арқылы ашыңыз. |
| «VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY жоқ» консольде | `.env.local` (жергілікті) немесе Vercel-дегі Environment Variables (жарияланған сайт) толтырылмаған. 2 және 4-бөлімдерді қараңыз. Бұл кезде сайт әлі де демо режимде ашылады — қате емес, ескерту. |
| Build қатесі (`npm run build`) | Алдымен `npm run typecheck` және `npm run lint` бөлек іске қосып, нақты қатені табыңыз. Node.js нұсқасы 20+ екенін тексеріңіз (`node -v`). |
| Supabase қатесі (кестеге қатынау жоқ, RLS қатесі) | Барлық миграциялар (`0001`–`0015`) **дәл ретімен** орындалғанын тексеріңіз (2-бөлім). `anon` кілтінің дұрыс екенін тексеріңіз — `service_role` кілтін фронтендте ешқашан қолданбаңыз. |
| Маршрутты жаңартқанда (F5) 404 | Vercel-де `vercel.json` файлы репозиторийдің түбірінде бар екенін тексеріңіз — ол React Router маршруттарын `index.html`-ге бағыттайды. |
| Суреттер (Талпын, автор фотосы) жүктелмейді | Файлдар `public/` қалтасында дұрыс жолмен жатқанын тексеріңіз; Supabase Storage-тен жүктелетін медиа үшін `0004_storage.sql` миграциясы орындалғанын және bucket-тің «public» екенін тексеріңіз. |

## 9. Жоба құрылымы

```text
src/
  components/        рөлге тәуелді бағыттарды қорғайтын ProtectedRoute
  data/topics.ts      113 тақырыптың толық тізімі (жалғыз дерек көзі)
  features/auth/      кіру және тіркелу формалары
  features/lesson/     "Көр–Құрастыр–Түсіндір–Қолдан–Бекіт" интерактивті қозғалтқышы
  hooks/useAuth.tsx    сессия мен профильді бақылайтын контекст
  layouts/             жоғарғы панель мен футер
  lib/                 Supabase клиенті, файл жүктеу көмекшісі
  pages/               әр маршрутқа сәйкес бет
  types/database.ts    Supabase кестелерінің TypeScript түрлері
supabase/migrations/   нөмірленген SQL миграциялары (2-бөлімді қараңыз)
scripts/checkTopicCount.ts   113/60/53 тақырып санын тексеретін скрипт
public/                Талпын, инфографика, автордың фотосы
```

Тексерулерді қолмен іске қосу:

```bash
npm run typecheck     # TypeScript қателерін тексереді
npm run lint           # ESLint
npm run build           # production сборкасы (tsc + vite build)
npm run check:topics    # тақырып санын тексереді (113 = 60 + 53)
npm run check:content   # әр тақырыптың мазмұнын тексереді (кезеңдер, дұрыс жауап,
                         # түсіндірме, кеңес, бос конфигурация жоқтығы)
```

## 10. Не істелген, не істелмеген

### Толық жұмыс істейді

- Тіркелу, кіру, шығу (Supabase Auth), рөлдер (`student`/`teacher`/`admin`),
  өзіне-өзі рөл тағайындау мүмкін емес (RLS деңгейінде қорғалған).
- Барлық 13 кесте, RLS саясаттары, файл қоймасы саясаттары (SQL миграциялары).
- Барлық 113 тақырыптың каталогы (сынып/бағыт бойынша сүзу, іздеу), дерекқордан
  нақты сұрау арқылы.
- **Барлық 113 тақырықтың бәрі толық интерактивті сабаққа айналдырылған**
  (сынып пен бағыт бойынша толық тізім төменде):
  - «10 көлеміндегі сандардың құрамы» (1-сынып, негізгі) — флагман сабақ: 5
    кезең, Бекіт бөлімінде 5 түрлі формат (бос орын, таңдау, сәйкестендіру,
    қатені табу, практикалық есеп);
  - 1-сынып «Логика» бағытының барлық 15 тақырыбы;
  - 2-сынып «Логика» бағытының барлық 12 тақырыбы (теңдеу, периметр, тиімді
    есептеу, кесу/ағаш егу есептері, өлшем бірліктерін салыстыру, өлшеу мен
    құю, тақ/жұп сан, комбинаторика, кері шегіну, қарапайым логика ж.б.);
  - 3-сынып «Логика» бағытының барлық 15 тақырыбы (тиімді тәсіл, теңдеу
    логикасы, сандар қатары, мәтін есептер, фигураларды санау, комбинаторика,
    үлес, аудан (SVG торкөз сызбамен), жиын, қосынды/еселік айырма, жасқа
    байланысты есептер, жорамалдау тәсілі ж.б.);
  - 4-сынып «Логика» бағытының барлық 11 тақырыбы (сан/цифр, арифметикалық
    тепе-теңдіктер, логикалық амалдар, периодтық есептер, жою тәсілі, аудан,
    қозғалыс есептері, тепе-теңдік/таразы есептері, комбинаторика, тиімді
    көбейту/бөлу, артық қалу және жетпей қалу мәселесі).

  **«Логика және функционалдық сауаттылық» бағытының барлық 53 тақырыбы осымен
  толық аяқталды (1, 2, 3 және 4-сынып).**
  - 1-сынып «Негізгі математика» бағытының қалған барлық 14 тақырыбы (20

  арқылы мұғалім тек өзі құрған тақырыптарды өңдей алады (әкімші — барлығын);
  дайын 113 жүйелік тақырыптың мазмұнын толық өзгерту әлі тек әкімшіге ашық

  көбірек). **Серия (streak)** — `progress.completed_at` мерзімдерінен есептеледі

  аяқталғаны. **Деңгей** — аяқталған тақырып санына негізделген 5 атаулы
  деңгей («Іздеуші» → «Тау патшасы», әрқайсысы 5 тақырықтан), Кабинетім бетінде
  әрдайым көрінеді, ал деңгей жаңа көтерілгенде сабақ нәтижесі бетінде арнайы
  хабарлама мен әуен шығады. `prefers-reduced-motion` қосулы болса, конфетти
  анимациясы автоматты өшеді.

### «Қозғалтқыш» кеңейтуі (жаңа интерактив түрлері мен Талпынның нақты өзгеретін бет-әлпеті)

Пайдаланушының сұрауы бойынша («профессиональный платформаға сәйкес жасау,
Талпын графикасы өзгеріп отырсын») алдымен қайта пайдаланылатын құрылыс
блоктары («қозғалтқыш») кеңейтілді, содан кейін тақырыптардың мазмұны
сыныппен реттелетін болады (келесі кезең):

- **Талпынның бет-әлпеті енді код арқылы салынған нақты SVG сурет**
  (`TalpynSvg.tsx`) — суретті генерациялау құралы жоқ болғандықтан, жеті
  сурет тапсырыс берудің орнына Талпынның көзі, аузы және қосымша
  элементі әр күйге (`greeting`/`hint`/`thinking`/`success`/`support`/
  `pointing`/`finish`) сай **нақты қайта сызылады** — бұл жай ғана
  түс/эмодзи ауыстыру емес, шынымен басқа пішінді SVG жол. Мысалы,
  `success` күйінде көз жарты ай тәрізді қуанышты пішінге ауысады,
  `thinking` күйінде бір қасы көтеріледі, `finish` күйінде басына
  шағын жұлдыз-тәж қосымша элементі шығады. Бұрынғы статикалық
  `/mascot/talpyn-greeting.png` суреті енді қолданылмайды.
- **Бекіт кезеңінің тапсырма түрлері 3-тен 7-ге дейін кеңейтілді**:
  көп таңдау, қысқа жауап, сәйкестендіруге қоса — **сұрыптау**
  (`SortingTask` — элементтерді жоғары/төмен батырмасымен дұрыс ретке
  қою), **топтастыру** (`GroupingTask` — әр затты екі топтың біріне
  батырмамен жатқызу), **өрнек құрастыру** (`ExpressionBuilderTask` —
  «текшелерді» ретімен басып, дұрыс өрнек/теңдеу құрастыру), **қатені
  табу** (`FindErrorTask` — бірнеше қадамның ішінен қате жол бас
  тидару). Барлығы пернетақта/тышқан/сенсормен қолжетімді батырма
  негізінде жасалған (нативті HTML5 drag-and-drop емес — бұл қолданыстағы
  «сәйкестендіру» тапсырмасындағыдай, барлық құрылғыда тұрақты жұмыс
  істеу үшін саналы түрде таңдалған тәсіл). `BekitStage.tsx`-тегі
  диспетчер жаңа төрт түрді дұрыс тапсырма компонентіне бағыттайды;
  `block_type` ENUM-де жоқ екі түр (`expression_builder`, `find_error`)
  `'question'` block_type + `configuration.kind` арқылы сақталады —
  дерекқор миграциясы қажет болмады.
- **Көр кезеңіне жаңа «scene» түрі қосылды** (`SceneStage.tsx`): бір
  мәтіндік слайдтың орнына, бірнеше байланысты затты бір мезгілде
  көрсететін SVG жақтаудағы белгіше-карталар қатары (мысалы, «алма,
  алмұрт, шие» бір суретте, әрқайсысының атауымен). `KorRenderer.tsx`
  оны `configuration.kind === 'scene'` бойынша таниды.
- **`scripts/generateLessonSeed.ts` генераторы жаңартылды** — енді
  жоғарыдағы барлық жаңа Бекіт түрлерін және Көр «scene» түрін де SQL-ге
  түрлендіре алады, сондықтан келесі кезеңде (сыныптарды бірінен соң бірін
  жаңа түрлермен байыту) бұл құрал әлі де қолданылады. Барлық 113 қолданыстағы
  тақырып осы жаңартылған генератормен қайта тексерілді — регрессия жоқ,
  бәрі бұрынғыдай дұрыс SQL шығарады (себебі олар әлі ескі түрлерді
  қолданады).
- **Мұғалімнің визуалды конструкторы да кеңейтілді**: «Көр» түрін
  таңдау (слайд/scene), «Бекіт» тапсырма түрін таңдау тізіміне барлық 7
  түр қосылды — мұғалім енді сұрыптау, топтастыру, өрнек құрастыру, қатені
  табу тапсырмаларын да интерфейс арқылы толық авторлай алады (дерекқорға
  тікелей SQL жазусыз).

**Осы кезеңнен кейін де ашық қалатын шектеу** (адалдық үшін): жоғарыдағылардың
бәрі — жаңа мүмкіндіктер, «қозғалтқыш». 113 тақырыптың нақты мазмұны (Бекіт
тапсырмалары, Көр слайдтары) әлі ескі, тар жинақтағы түрлерді қолданады —
жаңа 4 Бекіт түрі мен «scene» Көр түрін нақты тақырыптарда пайдалану әлі

### Техникалық аудиттен кейінгі түзетулер (ақ экран, демо режим, тағы 2 тапсырма түрі)

Пайдаланушы жіберген толық техникалық аудит-брифі бойынша тексеріліп, нақты

  жүктелместен бұрын бұл танылып, брифте сұралған дәл мәтінмен ескертеді.
- **Демо режим**: `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` жоқ кезде
  клиент фиктивті `placeholder.supabase.co` адресіне нақты сұрау салмайды
  (`useAuth.tsx` бұл жағдайда Supabase-ке мүлдем қатынамайды). Бас бет пен
  тақырыптар каталогы `src/data/topics.ts` жергілікті тізімінен көрсетіледі
  (`DemoModeBanner` ескерту жолағымен), ал кіру/тіркелу/сабақ мазмұны

  сақталады).
- **Мазмұнды автоматты тексеру құралы қосылды** (`npm run check:content`,
  `scripts/checkLessonContent.ts`): барлық 112 мазмұн-модуль тақырыбын
  (флагман тақырып бөлек SQL-де жазылған, ол каталогпен бөлек салыстырылады)
  `src/data/topics.ts` каталогымен атауы/сыныбы/бағыты бойынша дәл салыстырады
  және әр тақырыпта: 5 кезеңнің де мазмұны бар ма, Бекіт кезеңінде кемінде 3
  тапсырма бар ма, әр тапсырма түрінде дұрыс жауап/түсіндірме/кеңес бос емес
  пе, бос конфигурация (мысалы, бос `items`/`tiles`/`pairs` тізімі) жоқ па —
  тексереді. Қазір барлық 112 тақырып бұл тексеруден өтеді.
- **Бекіт кезеңіне тағы 2 тапсырма түрі қосылды** (брифтегі
  `VisualMatchingTask` пен `MeasurementTask` сұранысы бойынша): **сурет-атау
  сәйкестендіру** (`VisualMatchingTask` — сурет пен оның атауын басып
  сәйкестендіру, сандық сәйкестендіруден бөлек), **сызғышпен өлшеу**
  (`MeasurementTask` — SVG сызғыштағы белгілерді санап, заттың ұзындығын
  дұрыс санмен таңдау). Екеуі де мұғалімнің визуалды конструкторынан
  авторланады. Осымен Бекіт кезеңінің тапсырма түрі саны 9-ға жетті.
- `npm ci` таза лездамамен (`package-lock.json`) сәтті орындалатыны, RLS-тегі

  расталды.

**Осы кезеңнен кейін де ашық қалатын, брифте сұралған, бірақ әлі жасалмаған
жұмыс** (адалдық үшін): барлық 113 тақырыпты жеке-жеке мазмұндық/педагогикалық
тұрғыдан қолмен шолу (тек автоматты құрылымдық тексеру бар, мағыналық
дұрыстықты адам тексеруі әлі қажет); толық Postgres-те барлық миграцияны қайта

### Дизайн мен анимация толықтырулары

- **Skeleton-жүктеу нақты түзетілді** — `.skeleton-block` класы 11 бетте
  қолданылып тұрған, бірақ CSS-те **ешқашан анықталмаған** екен: іс жүзінде
  ол мөлдір/бос тіктөртбұрыш болып көрінетін (фон түссіз, анимациясыз). Енді
  нақты жылтылдайтын (shimmer) градиент-анимациямен анықталды.
- **Мобильді төменгі навигация қосылды**: 900px-тен тар экранда topbar-дың
  `<nav>` толық жасырылатын, бірақ орнына ештеңе қойылмайтын — мобильді
  пайдаланушыда браузердің «артқа» батырмасынан басқа шарлау мүмкіндігі
  болмайтын. Енді экран төменінде бекітілген навигация жолағы бар (Басты /
  Тақырып / Әдістеме / рөлге сай кабинет).
- **Беттер арасындағы өту анимациясы**: әр маршрут ауысқанда негізгі мазмұн
  жеңіл fade+rise анимациясымен пайда болады (`MainLayout.tsx`-тегі
  `location.pathname` бойынша `key`).
- **Карталардың пайда болу анимациясы**: тақырып пен әдістеме карталары
  бірінен соң бірі сатылап (stagger) пайда болады.
- **Модаль терезенің ашылу анимациясы**: fade+scale әсерімен ашылады.
- **Дұрыс/бұрыс жауапқа реакция**: `.form-success`/`.form-error`
  хабарламалары жеңіл «pulse» әсерімен пайда болады — түс өзгеруі ғана емес,
  нақты оқиға сезілетіндей.
- **Прогресс шеңбері енді нақты толады**: `LessonPage`-тегі пайыз көрсеткіші
  бұрын тек мәтін болатын, енді conic-gradient арқылы шеңбер нақты пайызға
  сай толады.
- **Focus/hover/active/disabled күйлері жүйеленді**: пернетақтамен
  басқарғанда көрінетін фокус контуры (`:focus-visible`), батырмалардың
  hover/active қимылы, өшірілген (disabled) күйдің бәрі бірыңғай.
- Барлығы `prefers-reduced-motion: reduce` арқылы өшеді (жаңа анимациялардың
  әрқайсысында бөлек медиа-ережесі бар).
- Дизайн жүйесі өзгерген жоқ: ашық фон, бирюза/көк/сары акценттер, қалыпты
  әдістемелік стиль сақталды.

### Әлі толық жүзеге аспаған (адал тізім)

Бриф өте үлкен — толық коммерциялық өнім көлеміндегі жүздеген экран мен ондаған
тапсырма түрін бір отырыста өндіру мүмкін емес. Төменде нақты не жоқ екені жазылған;
бұл функциялар интерфейсте «жұмыс істеп тұрған» болып көрсетілмеген:

- **Барлық 113 тақырыптың мазмұны толтырылды** — «Бұл тақырыпқа әлі мазмұн
  қосылмаған» деген бос күй хабары енді ешбір тақырыпта көрінбеуі керек (егер
  көрінсе, ол SQL миграцияларының 2-бөлімде көрсетілген ретпен толық
  орындалмағанын білдіреді — барлық 15 миграцияны (`0001`–`0015`) қайта
  тексеріңіз). Болашақта мазмұнды жаңарту немесе кеңейту қажет болса,
  `src/data/lessonContent/` ішінде тақырып сипаттамасын жазып,
  `npx tsx scripts/generateLessonSeed.ts` арқылы жаңа SQL миграциясын
  автоматты түрде шығаруға болады — бұл барлық 113 тақырық үшін қолданылған
  дәл сол тәсіл.
- **Толық универсал тапсырма қозғалтқышы** — брифте сипатталған түрлердің
  көбі енді нақты жұмыс істейді: **сандық түзу** (`NumberLineStage` — санды
  түзудегі дұрыс белгіні басып табу), **сағат циферблаты** (`ClockStage` —
  SVG циферблаттан сағат пен минутты екі қадаммен таңдау), **тепе-теңдік
  таразы** (`BalanceScaleStage` — SVG таразы теңесу үшін керек санды тауып
  жазу, енгізген сайын таразы нақты еңкейеді), **ақша/дүкен сценарийі**
  (`MoneyStage` — бағасы көрсетілген заттардың жалпы сомасын есептеу),
  Бекіт кезеңінде **сұрыптау**, **топтастыру**, **өрнек құрастыру**,
  **қатені табу** (жоғарыдағы «Қозғалтқыш кеңейтуі» бөлімін қараңыз).
  Бұлардың бәрі мұғалімнің визуалды конструкторынан тікелей авторланады.
  Әлі жоқтары: заттарды тінтуірмен еркін сүйреп апару (нативті HTML5
  drag-and-drop — қазіргі «топтастыру»/«сәйкестендіру» батырма-негізді
  тәсілмен ауыстырылған), өлшеу құралдары (сызғыш/таразы бірліктерін
  интерактивті оқу), геометрия конструкторы (фигураны нүктелерден
  құрастыру) — бұл үшеуі әлі жоқ.
- **Конструктордың нақты шектеулері** (адалдық үшін): «Мұғалімнің визуалды
  конструкторы» жоғарыда сипатталғандай жұмыс істейді, бірақ мыналарды
  жасамайды: (1) ол тінтуірмен сүйреп апару (drag-and-drop) емес, жоғары/төмен
  батырмалары арқылы реттеу қолданады; (2) Құрастыр кезеңі үшін 6 түр ұсынады
  («санды құрастыру», «санау», «сандық түзу», «сағат», «таразы», «ақша») —
  сиқырлы шаршы, заңдылық, периметр/аудан, салыстыру сияқты қалған
  конфигурациялар осы беттен емес, тек `src/data/lessonContent/` +
  `generateLessonSeed.ts` арқылы жасалады;
  (3) дайын 113 жүйелік тақырыптың мазмұнын осы конструктормен өңдеу үшін
  әкімші болу керек (мұғалім тек өзі құрған тақырыптарды өңдей алады).

Осы тізімнен енді алынғандар (бұрын жоқ, енді толық жұмыс істейді): «Достижение/
ачивка беру логикасы», «Әкімшінің рөл тағайындау/бұғаттау экраны», «Мұғалімнің
медиа басқару экраны» және «Дыбықтар, конфетти, ойын динамикасы (серия/деңгей)»
— төртеуі де жоғарыдағы «Толық жұмыс істейді» бөліміне көшірілді.

### Жариялау алдындағы тексеруден шыққан түзетулер

Жариялауға дайындалу кезінде жасалған сыртқы шолу бірнеше нақты ақау тапты.
Тексеріліп, растап, мыналар түзетілді:

- **Аралық прогресс дұрыс сақталмайтын еді**: `progress.current_stage` бағаны
  оқушы қай кезеңде тұрса да әрдайым қате түрде `'bekit'` болып жазылатын
  (код деңгейінде қатты кодталған қате бар еді). Енді нақты ағымдағы кезең
  (`kor`/`qurastyr`/`tusindir`/`qoldan`/`bekit`) сақталады.
- **Оқушының нақты жауабы сақталмайтын еді**: `attempts.answer` бағанына
  оқушының нақты жауабының орнына тек блоктың ішкі идентификаторы
  (`{blockId: ...}`) жазылатын. Енді оқушы шынымен таңдаған/жазған жауап
  (таңдалған нұсқа мәтіні, жазған сан/сөз, сәйкестендірген жұптар) сақталады
  — бұл мұғалімнің нақты қай жауап берілгенін кейін тексеруіне мүмкіндік береді.
- **Бекіт кезеңінде көп таңдау тапсырмасында қате жауаптан кейін қайталау
  мүмкін болмайтын**: бұрын бір рет қате басқаннан кейін барлық нұсқалар
  мәңгілікке құлыпталып қалатын. Енді қате таңдалса, оқушы басқа нұсқаны
  таңдап, дұрысын тапқанша қайта көре алады (дұрыс жауап табылғанда ғана
  құлыпталады, қысқа жауап тапсырмасындағыдай).
- Қазақша интерфейсте қалып кеткен орысша сөз («Ученик») табылып, «Оқушы»
  болып ауыстырылды (`HomePage.tsx`, `MethodologyPage.tsx`).
- Талпынды сипаттайтын қате сөз («аққар» — мағынасыз/қате сөз) «қар барысы»
  болып түзетілді.
- **Автор профилін өңдеу формасы әкімші кабинетіне қосылды** — бұрын README
  бұл функцияны жоқ деп есептейтін; енді әкімші автордың аты-жөнін, лауазымын,
  жұмыс орнын, санатын, еңбек өтілін, білімін, өзі туралы мәтінін және фотосын
  (файл жүктеу арқылы) осы беттен өзгерте алады, нақты Supabase-ке жазады.
- Талпынның жеті күйі (`greeting`/`hint`/`thinking`/`success`/`support`/
  `pointing`/`finish`) бұрын бір статикалық суретпен ғана ерекшеленетін
  (тек мәтін мен түс арқылы). Бастапқыда әр күйге эмодзи-белгі мен CSS қимыл
  қосылған болатын; кейін, «Қозғалтқыш кеңейтуі» бөлімінде сипатталғандай,
  бұл толық SVG-суретке (`TalpynSvg.tsx`) ауыстырылды — енді әр күйде
  Талпынның көзі, аузы және қосымша элементі шынымен басқаша сызылады.

**Сол кездегі шектеулердің жаңа күйі**: Бекіт кезеңінің тапсырма түрлері
«Қозғалтқыш кеңейтуі» бөлімінде сипатталғандай 3-тен 7-ге дейін кеңейтілді
(сұрыптау, топтастыру, өрнек құрастыру, қатені табу — қосымша) және Көр
кезеңіне «scene» (сурет-карталар) түрі қосылды. Бірақ **113 тақырыптың нақты
мазмұны әлі осы жаңа түрлерді пайдаланбайды** — Бекіт тапсырмаларының басым
бөлігі әлі де қысқа жауап пен көп таңдау форматында, Көр кезеңінің басым
бөлігі әлі де мәтіндік слайд түрінде («StorySlides»). Жаңа түрлер — әзірге
тек мұғалімнің жаңа тақырып авторлауына арналған қозғалтқыш; дайын 113
тақырыпты жаңа түрлермен байыту — келесі кезеңнің (сыныппен-сыныппен) жұмысы,
әлі аяқталмаған. Бұлардың бәрі жоғарыдағы «Әлі толық жүзеге аспаған»
бөлімінде де көрсетілген.

### Орындалған тексерулер

- `npm install` — қатесіз аяқталды.
- `npm run typecheck` (`tsc -b`) — 0 қате.
- `npm run lint` — 0 қате, 1 зиянсыз ескерту.
- `npm run build` — сәтті аяқталды (production бандл шығарылды).
- `npm run check:topics` — 113 = 60 (негізгі) + 53 (логика), 15 тақырыптан
  әр сынып/бағыт торында (2-логика мен 4-логикадан басқа — брифтің өз тізіміндегі
  саны бойынша, тиісінше 12 және 11).
- Барлық 15 SQL миграциясы (`0001`–`0015`) осы сессияда жергілікті Postgres 16
  дерекқорына (Supabase-тің `auth`/`storage` схемаларын симуляциялап) ретімен
  іске қосылып, қатесіз орындалғаны тексерілді; **барлық 113 тақырықтың**
  әрқайсысында 5 кезең мен дұрыс сандағы блок бар екені, әр көп таңдау
  (multiple_choice) тапсырмасында дәл 4 жауап нұсқасы бар екені, және енді
  `draft` күйінде бірде-бір тақырып қалмағаны SQL сұрауымен расталды. Бір
  сессияда `scripts/generateLessonSeed.ts` генераторында нақты қате табылып
  түзетілген болатын: топтама ішінде бірдей атаумен екі "бекіт" тапсырмасы
  болса, генератор оларды SQL-де атауы бойынша ажырата алмай, сұрақ/жауап
  нұсқаларын қайталап кірістіріп жіберетін. Түзетуден кейін ажырату атау
  бойынша емес, әр тапсырманың бірегей `sort_order` мәні бойынша жасалады, және
  барлық миграциялар (0008–0011) осы түзетілген генератормен жасалып, әрқайсысы
  жеке-жеке қайта тексерілді. Бұл нақты Supabase жобасына қарсы тексеру емес
  (ол құралдың желі саясаты бойынша supabase.co доменіне тікелей қосыла
  алмайды) — RLS саясаттарының нақты Auth/Storage тіркелгілерімен тәртібін
  2-бөлімдегі қадамдарды өзіңіз орындағанда тексеріңіз.
- Тіркелу/кіру формалары, файл жүктеу валидациясы (`src/lib/storage.ts`) код
  деңгейінде жазылған және логикасы тексерілген, бірақ **нақты Supabase аутентификация
  ағыны арқылы ұшпен тексерілмеген** — сол себепті де желі шектеуі.
